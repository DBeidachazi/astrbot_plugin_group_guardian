# QQ群智能守护者 (GroupGuardian) – 项目概述

**累计反思 35 次**

## 1. 项目简介

GroupGuardian 是面向 AstrBot（Python 3.10+）的综合 QQ 群管理插件，提供 28 项群管功能、AI/LLM 审核、SQLite 词库与日志、OCR/视觉审核、防刷屏、名片监控、自适应词库学习及 AstrBot Dashboard WebUI。支持 OneBot 生态（NapCat、LLOneBot 等），通过 `register_web_api` 复用 Dashboard 鉴权，不启动独立 Web 服务。

## 2. 技术栈与结构

- 存储：`group_guardian.db`（运行时日志/状态）与 `lexicon.db`（外置词库）
- 审核：Aho-Corasick/纯 Python Trie + 正则回退 + LLM 二审；支持上下文、嵌套消息、Base 编码、OCR/GIF/表情和全量 AI 模式
- 主要模块：`main.py` 入口；`commands.py` 命令；`moderation.py` 审核；`anti_flood.py` 刷屏；`card_monitor.py` 名片；`appeal.py` 申诉/解禁；`membership.py` 权限；`storage.py` 持久化；`web.py` Web API；`llm_tools.py` AI 工具；`onebot.py` 协议适配；`scheduler.py` 调度；`pages/dashboard/` 前端

## 3. 开发与审查约定

1. **Mixin/MRO**：`Main` 的继承清单决定运行时 API。迁移方法必须检查直接/间接 `self.xxx` 依赖、MRO 覆盖、所有命令/WebUI/后台入口及初始化状态；命令入口优先委托 Web/业务层共享实现，避免重复处罚逻辑。
2. **高风险远程操作**：WebUI 确认、撤回、禁言、学习须重新校验权限、二次确认、状态与审计；检查重复点击、并发、部分失败、重试和平台撤回时效。失败时不得错误标记处罚或学习完成。
3. **稳定关联**：复核/日志操作优先使用消息 ID、审核 ID 等持久化唯一标识。群、用户、文本、时间只能辅助匹配；旧数据回退仅在候选唯一时绑定，0 个或多个候选均禁止猜测并应可观测。集合键不得用单值字典覆盖。
4. **审核控制流**：通过词、拒绝词、通用词库和广告规则优先级必须显式定义；新旧流程和多个开关须覆盖全部组合。功能未启用不等于消息已处理，禁止无依据提前 `return` 导致漏审；新增流程必须保留默认关闭和非目标事件的旧行为。
5. **异步协议**：含 `yield` 的 `async def` 是异步生成器，调用必须 `async for`，测试替身也必须保持同一返回协议。测试应区分单元、真实路由、权限失败、平台失败和端到端证据。
6. **协议脏数据**：OneBot 的 `comment`、引用块、拼入原文及 `[图片]` 占位符可能不是用户实际输入；审核前剥离并区分文本重复检测与消息频率统计，覆盖引用混合、多层嵌套及不同图片场景。
7. **配置与兼容**：新增开关/别名同步 `_conf_schema.json`、README、帮助输出及群级覆盖；自定义 LLM 提示词须保留格式约束、解析失败回退和超时/并发边界。外部库需 `ImportError` 降级并警告。记录 OneBot 实现差异。
8. **工具 Schema**：最终 JSON Schema 优先于声明表面。所有数组必须有合法 `items`；Gemini 会校验全部工具，一个非法声明可阻断整次请求。按工具名测试，不依赖声明数组索引；修改注解前确认 AstrBot 版本的 Schema 生成优先级。
9. **Issue 研判**：需求已存在用 `question`+`documentation`；新增功能为 `enhancement`，缺陷为 `bug`，绕过审核/提权/漏审倾向 `high`；截图信息不足先 `question`；垃圾推广直接关闭。标题去情绪、≤5 字标题需改写，`good first issue` 需考虑多文件与贡献门槛。
10. **重复检测可审计**：声明检索范围、关键词、候选和结论；比较触发条件、根因、影响与修复点，置信度低于 0.7 不输出。不得同时写“未发现重复”和“可能重复”；相似编号或关键词不是重复证据。

## 4. 近期重点经验

- WebUI 远程广告复核方法从 `CommandsMixin` 迁移到 `WebMixin` 后，要验证命令委托、MRO、权限审计及撤回/禁言/学习的部分失败一致性。
- 旧日志回退关联中，`group_id+user_id+content` 非唯一；同用户重复广告、多条 pending 必须使用候选列表，一对一且唯一才操作，否则隐藏按钮/人工确认。
- 视频统一审核的 `_submit_ad_review` 若为异步生成器不可 `await`；统一审核关闭时不能因视频信号直接终止链接、规则、LLM 后续审核。需验证重复入队、`source=video`、消息 ID 和撤回窗口。
- 学习状态必须完整贯通“写入→查询→路由→动作”：`ad` 与 `ok` 语义不同，放行不能继续复核/处罚；非广告名片不能因广告复核开关而跳过原有自动还原。
- 批量工具的 `user_ids` 必须生成 `{"type":"array","items":{"type":"string"}}`；先修正文档 `list[string]` 并检查最终 Schema，再决定是否同步 Python 注解。Gemini 的 400 发生在工具执行前；需按工具名回归并确认默认注册范围。

## 5. 质量底线

高风险审核功能默认关闭新增自动动作；自动学习必须候选审批或通过多维门槛。任何自动撤回、禁言、踢人和名片还原都应保留人工可审计记录。文档、CHANGELOG、配置和测试必须随行为变更同步；不能以“测试总数通过”替代针对唯一性、异步类型、开关组合、权限和失败场景的证据。
